Livelock Detection Using Cycle Decomposition in a Model Checker

Harshita Lila · Aayushi Gautam · Prof. Gene Cooperman — Northeastern University / McMini

I developed a livelock-detection heuristic for McMini, an in-situ stateless model checker for concurrent programs. The work addresses executions in which threads continue to execute but fail to make meaningful progress.

  • Developed a cycle-decomposition approach for identifying interacting groups of threads involved in livelock.
  • Used visible-object sharing, including mutexes, semaphores, condition variables, and shared variables, as a runtime approximation for thread interaction.
  • Designed the approach to analyze bounded execution suffixes rather than exhaustively enumerate schedules.
  • Produced shorter and more interpretable livelock witnesses.
  • Established soundness conditions and characterized limitations involving nondeterminism and progress annotations.

Model CheckingConcurrencyFormal VerificationLivelock

Technical details

In an in-situ stateless model checker such as McMini, only transitions already executed on the current branch are observable, so the full happens-before relation is unavailable at runtime. The approach approximates thread interaction using visible-object sharing: two transitions are considered related when they access a common visible object such as a mutex, semaphore, condition variable, or shared variable. This is a sound over-approximation of happens-before.

The algorithm decomposes the set of threads into independent subsets, each cycling without progress, and searches each subset for state recurrence within a bounded execution suffix. It thereby avoids both exhaustive schedule enumeration and cross-schedule state caching. The result is a short, per-cycle livelock witness that a developer can inspect directly.

Soundness conditions were established under explicit assumptions, including developer-annotated progress points, and known limitations were characterized — for example, potential false positives arising from nondeterministic synchronization such as sem_post().

McMini — DPOR-Based Model Checker

Open-source contribution — Northeastern University

I contributed to McMini, an open-source DPOR-based model checker for multithreaded programs developed at Northeastern University.

  • Developed an LLVM instrumentation plugin for monitoring global-variable accesses.
  • Added runtime handling for reads and writes to support data-race-related analysis.
  • Implemented usability improvements and command-line options.
  • Worked on concurrent synchronization mechanisms and model-checking infrastructure.
  • Contributed to transparent checkpointing and systems-level debugging.
